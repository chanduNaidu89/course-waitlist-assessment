# Course Waitlist Service

A Spring Boot service that handles **enrollment, dropping and FIFO waitlist promotion for one course
offering**, using an in-memory store. No starter project was supplied, so this follows the assessment's
fallback: a minimal service with an in-memory store. There is no database, frontend or auth.

This README explains how to **build, run and test** the application. The other assessment
deliverables are:

| Document | Contents |
|---|---|
| [`DESIGN.md`](DESIGN.md) | Design spec: service boundary, API, invariants, waitlist-promotion rule, concurrency, assumptions, tradeoffs, limitations (§8) |
| [`AI_USAGE.md`](AI_USAGE.md) | AI prompts, responses, accept/edit/reject decisions, verification evidence |
| [`IMPLEMENTATION_STEPS.md`](IMPLEMENTATION_STEPS.md) | Step-by-step guide to how the solution was built |

## 1. Prerequisites

| Tool | Version | Check |

| Maven | 3.9+ | `mvn -v` |

## 2. Quick start

Run these from the project root, the folder that contains `pom.xml`:

```bash
./run.sh unit     # 1. JUnit tests         -> Tests run: 133, Failures: 0, Errors: 0
./run.sh test     # 2. curl scenario tests -> functional 134 passed, concurrency 17 passed
./run.sh          # 3. run the app on http://localhost:8080 (Ctrl+C to stop)
```

With the app running, open **http://localhost:8080/swagger-ui.html** for interactive API docs (§5.1).

If `./run.sh` says "permission denied", run `chmod +x run.sh scripts/curl-tests.sh` once.

---

## 3. Build

```bash
mvn clean package -DskipTests       # -> target/course-waitlist-0.1.0.jar
```

To build and run all tests in one go:

```bash
mvn clean verify
```

Without network access (dependencies already in `~/.m2`), add `-o`: `mvn -o clean package`.
For `run.sh`, use `MVN_FLAGS=-o ./run.sh ...`.

---

## 4. Run

| Command | What it does |
|---|---|
| `./run.sh` | Builds the jar and runs it on port 8080 |
| `PORT=9090 ./run.sh` | The same, on another port |
| `java -jar target/course-waitlist-0.1.0.jar` | Runs an already-built jar |
| `mvn spring-boot:run` | Runs straight from Maven |

The app is ready when the log shows `Started WaitlistApplication`. Quick check:

```bash
curl -s http://localhost:8080/api/offerings/CS201
# {"offeringCode":"CS201","capacity":2,"seatsAvailable":2,"prerequisites":["CS101"],"enrolled":[],"waitlist":[]}
```

### Seed data (`src/main/resources/application.properties`)

| Setting | Value |
|---|---|
| Offering | `CS201` |
| Capacity | `2` |
| Prerequisite | `CS101` |
| Eligible learners (completed CS101) | `alice`, `bob`, `carol`, `dave` |
| Known but **not** eligible | `erin` (completed only MATH100) |

Override any setting at startup, for example:

```bash
java -jar target/course-waitlist-0.1.0.jar --waitlist.capacity=5 "--waitlist.learners[frank]=CS101"
```

Use the **bracket form** `waitlist.learners[<id>]` for learner ids. Without brackets, Spring strips
characters such as `@` and `/` from map keys, so `jo@x.edu` would be stored as `jox.edu`.

State is in memory and **resets on every restart**.

## 5. API

### 5.1 Swagger UI (interactive API documentation)

With the app running (`./run.sh`), open:

| URL | What |
|---|---|
| **http://localhost:8080/swagger-ui.html** | Swagger UI. Browse the endpoints and send real requests with **Try it out** |
| http://localhost:8080/v3/api-docs | OpenAPI 3 spec (JSON), e.g. to import into Postman or generate a client |
| http://localhost:8080/v3/api-docs.yaml | The same spec in YAML |

Every endpoint documents each status code it can return, which `outcome` that code carries, and the
response schema (`EnrollResult`, `DropResult`, `OfferingSnapshot`, `ApiError`). Parameters come
pre-filled with working examples (`CS201`, `alice`). Swagger UI requests change the same in-memory
state as curl, so restart the app before running the curl suites by hand.

The docs are generated by [springdoc-openapi](https://springdoc.org) 2.8.13 from annotations in
`EnrollmentController` and the DTOs. API metadata is in `config/OpenApiConfig`.

### 5.2 Endpoints

Base path: `/api/offerings/{offeringCode}`. Only the configured offering exists (`CS201`); any other
code returns `404 OFFERING_NOT_FOUND`.

Every response body includes a machine-readable `outcome` and a human-readable `message`.

### Enroll: `POST /api/offerings/CS201/enrollments`

```bash
curl -s -X POST http://localhost:8080/api/offerings/CS201/enrollments \
     -H 'Content-Type: application/json' -d '{"learnerId":"alice"}'
```

| HTTP | `outcome` | When |
|---|---|---|
| 201 | `ENROLLED` | A seat was free and the learner meets the prerequisite |
| 202 | `WAITLISTED` | The offering is full; the learner joined the end of the waitlist (`waitlistPosition` is returned) |
| 200 | `ALREADY_ENROLLED` / `ALREADY_WAITLISTED` | Duplicate request; nothing changed |
| 422 | `PREREQUISITE_NOT_MET` | Prerequisite missing; the learner is neither enrolled nor waitlisted |
| 404 | `LEARNER_NOT_FOUND` | Unknown learner id |
| 400 | `INVALID_REQUEST` | Blank, padded or over-long (>64 characters) id; missing or malformed body |

### Drop: `DELETE /api/offerings/CS201/enrollments/{learnerId}`

```bash
curl -s -X DELETE http://localhost:8080/api/offerings/CS201/enrollments/alice
```

| HTTP | `outcome` | When |
|---|---|---|
| 200 | `DROPPED` | The seat was released. `promotedLearnerId` is the earliest eligible waiter who got it; `removedIneligible` lists waiters who were skipped and removed |
| 200 | `LEFT_WAITLIST` | The learner was on the waitlist and has been removed |
| 404 | `NOT_ENROLLED` | Neither enrolled nor waitlisted (includes repeated drops); nothing changed |
| 400 | `INVALID_REQUEST` | Invalid id |

### State: `GET /api/offerings/CS201`

Returns `capacity`, `seatsAvailable`, `prerequisites`, `enrolled[]` and `waitlist[]`, both lists in order.

### Waitlist rules in brief

See `DESIGN.md` §4 for the full rules.

- **Ineligible when enrolling:** the request is rejected and the learner is never waitlisted.
- **Ineligible on reaching the front of the waitlist** (e.g. a prerequisite was revoked while waiting):
  the learner is **skipped and removed**, and the next learner in line is checked.

## 6. Test

### 6.1 JUnit tests (no running app needed)

```bash
./run.sh unit        # or: mvn test
```

Expected output:

```
Tests run: 133, Failures: 0, Errors: 0, Skipped: 0
BUILD SUCCESS
```

| Test class | Tests | Covers |
|---|---|---|
| `service/EnrollmentServiceTest` | 32 | Seats available, offering full, duplicate requests, FIFO promotion, prerequisite failure and the skip policy, capacity edge cases, invalid and repeated drops. Every test also checks that capacity is respected, no learner appears twice, and the waitlist stays in order |
| `service/EnrollmentServiceConcurrencyTest` | 80 (4 × 20 runs) | Parallel enrolls with racing duplicates, parallel drops with racing repeats, the skip policy under contention, mixed enrolls and drops |
| `controller/EnrollmentControllerTest` | 13 | End-to-end HTTP through MockMvc with the real config: status codes 400/404/405/406/415/422, headers, full workflow |
| `controller/LearnerBindingTest` | 3 | Config binding of learner ids |
| `controller/OpenApiDocsTest` | 2 | `/v3/api-docs` describes every endpoint, status code and outcome; Swagger UI is served |
| `exception/ApiExceptionHandlerTest` | 1 | 500 responses use the standard shape and don't leak exception text |
| `config/OfferingPropertiesTest`, `domain/CourseOfferingTest` | 2 | Config validation |

Run a single class or group:

```bash
mvn test -Dtest=EnrollmentServiceTest
mvn test -Dtest='EnrollmentServiceTest$FifoPromotion'
mvn test -Dtest=EnrollmentServiceConcurrencyTest
```

Reports are written to `target/surefire-reports/`.

### 6.2 curl scenario tests (against the running app)

```bash
./run.sh test
```

This builds the jar, then for each suite **starts a fresh app**, runs the suite, and stops the app. It
prints PASS/FAIL for every check and exits non-zero if any check fails. App logs go to
`target/run-logs/`.

Expected output, at the end of each suite:

```
functional suite: 134 passed, 0 failed
concurrency suite: 17 passed, 0 failed
==> curl suites: functional PASSED, concurrency PASSED
```

| Suite | Scenarios |
|---|---|
| `functional` (20 scenarios, 134 checks) | 0 initial state · 1 invalid requests change nothing · 2 errors 405/406/415 keep the `Allow`/`Accept` headers · 3 unknown offering · 4 unknown learner · 5 prerequisite failure with seats free · 6 enroll · 7 duplicate enroll · 8 offering becomes full · 9 ineligible learner not waitlisted when full · 10 waitlist in arrival order · 11 duplicate waitlist request keeps position · 12 drop promotes the first in line · 13 repeated drop · 14 drop of a non-member · 15 leave the waitlist · 16 re-enroll after a drop goes to the back · 17 successive FIFO promotions · 18 drop with an empty waitlist leaves the seat open · 19 the open seat is reused. **State is checked after every step.** |
| `concurrency` (17 checks) | 20 learners enroll at once, each with a duplicate sent at the same time: exactly 2 enrolled, 18 waitlisted, positions 1–18 unique, no duplicates. Then both seat holders drop twice at the same time: exactly 2 `DROPPED`, 2 `NOT_ENROLLED`, and the first 2 waiters promoted. |

To run a suite against an app you started yourself (it must be **freshly started**):

```bash
./run.sh                                    # terminal 1
scripts/curl-tests.sh functional            # terminal 2
BASE_URL=http://localhost:9090 scripts/curl-tests.sh functional   # if you used another port
```

The `concurrency` suite needs 20 extra seeded learners (`c01`–`c20`), so run it through `./run.sh test`.

The curl tests can't reach one scenario: a learner becoming ineligible **while waiting**. That needs a
change to their course records, and the API has no endpoint for that. The JUnit tests cover it
(`EnrollmentServiceTest$PrerequisiteFailure`, `EnrollmentControllerTest.skipPolicyIsVisibleOverHttp`).

### 6.3 Run everything

```bash
./run.sh all         # JUnit tests, then both curl suites
```

## 7. Troubleshooting

| Symptom | Fix |
|---|---|
| `Could not self-attach to current VM` / Mockito `MockMaker` error in tests | Already handled: `pom.xml` loads Mockito as a `-javaagent`. If you changed the Surefire config, keep that `argLine`. |
| Test output shows `ERROR ... ApiExceptionHandler : Unhandled exception` | Expected, and not a failure: `ApiExceptionHandlerTest` deliberately triggers an unexpected exception to check the 500 response |
| Swagger UI shows a blank page or 404 | Use `/swagger-ui.html`, which redirects to `/swagger-ui/index.html`. Make sure the app was rebuilt after pulling (`./run.sh` rebuilds) |
| `Port 8080 is already in use` | Stop the other process, or use `PORT=9090 ./run.sh` |
| curl tests print `Cannot reach http://localhost:8080/...` | Start the app first (`./run.sh`), or use `./run.sh test`, which starts it for you |
| curl to `localhost` returns proxy errors | Add `localhost` to your `no_proxy` environment variable |
| Maven cannot download dependencies | Check network/proxy settings, or build offline with `-o` if `~/.m2` is populated |
| `release version 17 not supported` | Your JDK is older than 17. Install JDK 17+ and point `JAVA_HOME` at it |
| A curl suite fails after an earlier manual run | Restart the app; the suites expect fresh in-memory state |

## 8. Project layout

```
pom.xml                         Spring Boot 3.5.6, Java 17
run.sh                          build / run / test entry point
scripts/curl-tests.sh           curl scenario suites (functional, concurrency)
src/main/java/com/example/waitlist/
  WaitlistApplication.java      Spring Boot main class
  config/                       OfferingProperties (binds waitlist.*), WaitlistConfig (beans), OpenApiConfig (Swagger metadata)
  controller/                   EnrollmentController (HTTP -> service; outcome -> status code)
  service/                      EnrollmentService (all rules + state, one lock)
  dto/                          EnrollRequest, EnrollResult, DropResult, OfferingSnapshot, ApiError
  domain/                       CourseOffering, LearnerRecords, PrerequisitePolicy
  exception/                    ApiExceptionHandler, OfferingNotFoundException
src/main/resources/application.properties   offering + seed learners
src/test/java/com/example/waitlist/         JUnit tests (same package layout)
```
